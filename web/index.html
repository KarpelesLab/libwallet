libwallet · self-custodial · client-side only

Real backend · in your browser
This runs the actual libwallet backend — its SQLite database, TSS keygen and signing, and request handlers — compiled to WebAssembly and executing entirely on this device. State is session-only: the database lives in memory and is discarded on reload (durable storage needs DB serialization, a follow-up). Live balances and broadcast are unavailable here — the networking handlers are gated out of the browser build, which is exactly what lets every call run synchronously and offline.

Create a real wallet · TSS keygen

Runs a real 1-of-3 threshold (DKLs23, secp256k1) key generation in this tab. The three shares are each sealed with the password you enter — an all-local committee, no server.

Seals the shares with a hardware-backed secret derived from your device passkey (WebAuthn PRF) — nothing to type, and it never leaves the authenticator; each signature re-derives it with a biometric gesture.

Self-custody wallet with 2FA · RemoteKey

Creates a 1-of-3 wallet whose third share is a server-held RemoteKey, unlocked by a 2FA code sent to your email or phone. Two Password shares stay local; the RemoteKey adds recoverable 2-factor custody. Requires a Client ID above.
